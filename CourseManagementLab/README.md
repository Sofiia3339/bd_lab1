# Система управління навчальними курсами

Лабораторна робота з системного програмування. Вебзастосунок для школи програмування підтримує керування курсами й уроками, запис студентів, облік оплат і прогресу, відгуки та видачу сертифікатів.

**Технології** · C# · .NET 8 · ASP.NET Core MVC · PostgreSQL · Npgsql

## Реалізація

| Вимога | Як реалізовано |
| --- | --- |
| Реляційна модель | 16 таблиць у схемі `course_lab` |
| Логічне видалення | Курси, уроки та відгуки позначаються як видалені. Курси й уроки можна відновити |
| Аудит змін | Дата й автор останньої зміни, журнал змін курсів та історія цін |
| Об’єкти PostgreSQL | 13 збережених процедур, 5 функцій, 6 тригерів і 12 представлень |
| Індекси | B-tree для пошуку записів за студентом і GIN для повнотекстового пошуку курсів |
| Repository + Unit of Work | Репозиторії читають через представлення та записують через процедури. Запис на курс і оплата виконуються в одній транзакції |

Застосунок працює в демонстраційному режимі з вибором користувача у формі й тестовим обліком оплат.

## Запуск

Потрібні .NET 8 SDK і запущений PostgreSQL.

1. Створіть порожню базу `course_management_lab`.
2. Відкрийте Query Tool для цієї бази в pgAdmin і виконайте [Database/install.sql](Database/install.sql). Скрипт створює схему та додає тестові дані.
3. У локальній копії `appsettings.json` налаштуйте `ConnectionStrings:DefaultConnection` для свого PostgreSQL. Збережіть `Database=course_management_lab` і `Search Path=course_lab,public`. Для репозиторію залиште `Password=CHANGE_ME`.
4. Запустіть застосунок із папки, де лежить `CourseManagementLab.csproj`.

   ```bash
   dotnet run
   ```

5. Відкрийте [http://localhost:5080](http://localhost:5080).

## Перевірка

- Виконайте [Database/verify.sql](Database/verify.sql) у Query Tool. Скрипт виводить повідомлення `PASS` після успішної перевірки та відкочує зміни тестової транзакції.
- Змініть ціну курсу й перегляньте історію цін. Потім видаліть курс і відновіть його через список усіх курсів.
- Виберіть студента та курс без попереднього запису. Спробуйте запис із неправильною сумою оплати, а потім із правильною. У першому випадку транзакція скасовує запис, у другому зберігає і запис, і оплату.
